# VPP 中的优化器 DP 通信重叠

本目录研究如何在虚拟流水线并行（VPP）执行过程中，安排数据并行（DP）的梯度归约和参数收集，使通信与计算重叠。重点结合 `dots-score` 的实现和提交历史，说明通信何时可以发起、由谁发起，以及计算使用数据前需要满足哪些条件。

## 重点内容

- **通信时机**：按 VPP chunk、层或 owner 组织 grad-reduce、param-gather，分析它们与前向、反向和参数更新的依赖。
- **梯度与参数缓冲区**：bucket 划分、梯度就绪计数、梯度累积、缓冲区复用，以及通信完成前后的访问约束。
- **优化器配合**：Even Muon 等优化器的 owner、bucket 和执行生命周期如何影响通信安排。
- **异步执行约束**：CUDA stream、event/fence 和通信句柄如何协调，如何避免过早读取、重复发起通信或遗漏同步。
- **组合适配与验证**：多模态训练步骤、不同 VPP 配置下的执行差异，以及重叠效果、数值一致性和显存占用的验证。

## 与其他专题的关系

- [BigMac](../01_BigMac/README.md) 负责整体流水线调度；本目录细化其中的 DP 通信时序。
- [Muon](../10_Muon/README.md) 负责优化器算法、参数组织和更新实现；两者在 Even Muon 的执行生命周期上互相引用。
- [FSDP/HSDP](../04_FSDP_HSDP/README.md) 负责分片训练机制；涉及相似的通信操作时，需要明确各自的分片对象和执行条件。

阅读本专题需要 DDP、梯度缓冲区和分布式优化器的基础概念，可在具体案例中补充。后续资料重点保留通信时序、同步约束、相关 commit，以及故障复现和性能对比。
